# Creator Publish Hub

Веб-панель для публикации одного видео сразу в **YouTube (Shorts)**, **Instagram Reels** и **TikTok** через **официальные API**.
Загрузка → выбор аккаунтов → тексты/обложки/время → кнопка **«ОПУБЛИКОВАТЬ ВСЁ»** → реальные статусы и ссылки.

> Никаких паролей соцсетей, обходов CAPTCHA, неофициальных API и браузерной автоматизации. Только OAuth 2.0 и официальные эндпоинты.

## Что реально можно автоматизировать (проверено по документации, октябрь 2026)

| | YouTube | Instagram | TikTok |
|---|---|---|---|
| Подключение | OAuth Google (`youtube.upload`) | Instagram Login (`instagram_business_content_publish`) | Login Kit (`video.publish`, `video.upload`) |
| Тип аккаунта | любой канал | **только Business/Creator** | любой |
| Автопубликация **публично** | ✅ да | ✅ да | ⚠️ **только после аудита приложения TikTok**. Без аудита — только «Только я» (SELF_ONLY) |
| Без проверки приложения | ✅ (для себя; пока приложение в «Testing», токен живёт 7 дней → переведите в «In production») | ✅ в режиме разработки, если вы — тестер/админ приложения | ⚠️ публикации приватные, ≤5 пользователей за 24 ч |
| Альтернатива | — | — | ✅ отправка в черновики TikTok (`inbox`) → завершить 1 нажатием в приложении |
| Квоты | 100 загрузок/сутки на проект | 100 публикаций/24 ч на аккаунт | ~6 запросов/мин на пользователя, дневной лимит TikTok |
| Размер/длительность | до 256 ГБ | MP4/MOV, H.264/HEVC+AAC, 3 с–15 мин, ≤300 МБ | ≤4 ГБ, ≤10 мин (или меньше — лимит аккаунта) |
| Обложка | своя картинка (канал подтверждён) | картинка (`cover_url`) или кадр | кадр по времени |
| Отложенная публикация | планировщик панели | планировщик панели | планировщик панели |
| Нужен публичный URL | нет (файл отправляется с сервера) | **да** — Instagram сам скачивает видео по подписанной временной ссылке | нет (загрузка частями) |
| Итоговый статус | `processingDetails` → «Опубликовано» после `processed` | статус контейнера → `media_publish` → permalink | `status/fetch` → `PUBLISH_COMPLETE` |

Статус **«Опубликовано»** ставится **только** после подтверждения платформы. Черновики TikTok получают статус **«Требуется действие»**.

## Архитектура

```
Браузер ──HTTPS──► Next.js (UI + API, авторизация, загрузка частями) ──► SQLite (WAL) + файлы /data
                                                          ▲
                         Воркер (отдельный процесс) ──────┘  очередь с арендой задач, повторы, планировщик
                              └──► YouTube / Instagram / TikTok API
```

* **Next.js 15 + React 19 + TypeScript + Tailwind** — интерфейс и серверные маршруты.
* **SQLite** (better-sqlite3, WAL) — бесплатная, без отдельного сервера, лёгкий бэкап одной командой. Для одного пользователя надёжнее и проще PostgreSQL.
* **Воркер** (`src/worker`) — каждые 5 с запускает созревшие задачи (Europe/Berlin, переход на летнее/зимнее время учтён), берёт задачи с «арендой» (lease), продолжает загрузки после перезапуска, повторяет временные ошибки с экспоненциальной задержкой (до 6 попыток). Вкладка браузера не нужна.
* **Интеграции** — `src/lib/platforms/{youtube,instagram,tiktok}.ts`, общий интерфейс `PlatformAdapter`. Новая платформа = новый адаптер.
* **Аккаунтов сколько угодно**: «YouTube RU», «YouTube DE» и т. д. подключаются независимо.

### Почему не «чисто облачный бесплатный» хостинг

| Сервис | Проблема для видео в несколько ГБ |
|---|---|
| Vercel Hobby | тело запроса ≤4,5 МБ, функции ≤60 с, только некоммерческое использование |
| Cloudflare Workers/Pages | тело запроса ≤100 МБ, лимиты CPU; нет долгих загрузок по 30+ минут |
| Cloudflare R2 | хранение 10 ГБ бесплатно — подходит как склад, но не выполняет загрузку в соцсети |
| Supabase Free | хранилище 1 ГБ, файл ≤50 МБ, проект засыпает после 7 дней простоя |
| GitHub Actions | не сервер: нет постоянного URL для OAuth/Instagram, задачи ≤6 ч, cron неточный |

**Вывод:** полностью бесплатная *serverless*-схема не может надёжно обрабатывать многогигабайтные видео. Рекомендуемый вариант за **0 €**:

1. **Oracle Cloud Always Free** — ВМ Ampere (до 4 ядер / 24 ГБ ОЗУ), 200 ГБ диска, 10 ТБ трафика в месяц. Работает круглосуточно без вашего компьютера. Минусы: при регистрации нужна карта (списаний нет), в популярных регионах бывает нехватка ARM-мощностей, простаивающие ВМ Oracle может вернуть себе.
2. **Или** любой постоянно включённый домашний компьютер / мини-ПК / NAS.

В обоих случаях HTTPS-адрес даёт бесплатный **Cloudflare Tunnel** (без открытия портов). Подробно — [docs/DEPLOY.md](docs/DEPLOY.md).

## Быстрый старт (локально)

```bash
cd creator-publish-hub
npm install
cp .env.example .env.local      # заполните (см. комментарии)
npm run hash-password -- 'ваш-длинный-пароль'   # → ADMIN_PASSWORD_HASH
openssl rand -hex 32            # → SESSION_SECRET, ещё раз → ENCRYPTION_KEY
npx next build && npm start     # панель: http://localhost:3000
npm run worker                  # во втором терминале — фоновый обработчик
npm test                        # автотесты
```

Требуется `ffmpeg`/`ffprobe` (проверка видео без перекодирования).

## Безопасность
* Вход по паролю (scrypt-хэш), подписанная сессия (httpOnly, SameSite), лимит попыток входа.
* CSRF: все изменяющие запросы проверяются по заголовку `Origin`; OAuth — параметр `state` + PKCE (Google).
* OAuth-токены шифруются AES-256-GCM (`ENCRYPTION_KEY`); в журнале и интерфейсе токены вырезаются из ответов API.
* Загрузки: белый список расширений, очистка имён файлов, проверка ffprobe, лимит размера; обложки — проверка сигнатуры JPEG/PNG.
* Видео отдаётся наружу только по подписанной ссылке с истечением (для Instagram).
* Аккаунт можно отключить или удалить вместе с токенами; видео и публикации — удалить.
* `.env`, база и видео исключены из git.

## Тесты
`npm test` — 34 теста: время/DST, шифрование, проверка видео, идемпотентность «Опубликовать всё», планировщик, аренда задач и восстановление после перезапуска, повторы и изоляция ошибок, отмена/повтор, адаптеры YouTube/Instagram/TikTok (на моках официальных ответов), возобновляемая загрузка и ffprobe.
**Тесты на моках не доказывают реальную публикацию** — её нужно проверить на ваших аккаунтах.
